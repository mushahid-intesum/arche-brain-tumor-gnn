# GNN Architecture: Hierarchical Supervoxel-Segmentation Graph Neural Network

**File**: `gnn.py`

This is Phase 4 of the ARCHE brain tumor analysis pipeline. It takes 3D MRI volumes and segmentation masks as input, constructs tumor graphs where each node represents a tissue region, predicts which regions are structurally connected, and generates multi-level explanations for those predictions.

## 1. High-Level Overview

The architecture is a hierarchical Graph Neural Network that works with full 3D MRI volumes. Each segmentation node (a tissue region like enhancing tumor, edema, or necrotic core) contains internal supervoxels (small 3D clusters of similar voxels). A Transformer network aggregates the supervoxel features into a 64-dimensional node embedding. Four additional topology features are concatenated, giving a total of 68 dimensions per node. These node features are then processed by a GATv2 encoder and a multi-signal edge decoder to predict tissue connectivity.

The processing pipeline is:

1. Take the 3D MRI volume (4 modalities) and 3D segmentation mask
2. Run 3D SLIC to generate supervoxels (small homogeneous 3D regions)
3. Assign supervoxels to segmentation components based on spatial overlap
4. For each segmentation component, use a Transformer to aggregate its supervoxel features into a single node embedding (64-dim)
5. Compute intra-node topology features from the internal supervoxel graph (4-dim)
6. Concatenate embeddings and topology to form 68-dim node features
7. Build edges between segmentation nodes using KNN and tissue compatibility
8. Compute OCN structural features for candidate edges (5-dim)
9. Run the GATv2 encoder to produce final node embeddings (64-dim)
10. Use the 6-signal multi-signal decoder to predict link probabilities
11. Generate 3-level explanations for the top predictions

A separate flat graph baseline (with 35-dim handcrafted features, no supervoxels) exists in `ablation/flat_graph.py` and is used only for ablation experiments.

## 2. Hierarchical Graph Construction

The `build_hierarchical_graph` function builds the graph from full 3D volumes. Each node is a 3D segmentation component containing internal supervoxels.

Supervoxels are small 3D clusters of voxels (volumetric pixels) that share similar intensity properties. They are generated by the 3D SLIC algorithm, which is an extension of the popular 2D superpixel algorithm to three dimensions. Each supervoxel groups together roughly 20 to 100 voxels that have similar MRI signal characteristics.

The pipeline works as follows:

1. The 3D SLIC algorithm is run on the raw 4-channel MRI volume to generate approximately 500 supervoxels.
2. Background supervoxels (those mostly outside the tumor) are pruned away.
3. Each remaining supervoxel is assigned to the segmentation component it overlaps with most.
4. For each supervoxel, a 22-dimensional feature vector is computed (intensity statistics across all 4 channels, plus volume and shape descriptors). Three additional relative positional encoding values are appended, giving 25 dimensions per supervoxel.
5. Within each segmentation component, a KNN graph is built over its assigned supervoxels to capture their internal spatial relationships.
6. Between segmentation components, edges are built using KNN and tissue compatibility rules.

The resulting PyG Data object contains the standard fields (node features, edge index, positions, tissue labels) plus additional fields: `sv_features` (a list of tensors, one per node, containing the supervoxel feature matrices), `sv_edge_indices` (internal KNN graphs per node), and `n_svs_per_node` (count of supervoxels in each node).

**Tissue Compatibility Rules**: The tissue compatibility rules encode known spatial relationships in glioblastoma. Compatible tissue pairs for edge creation are: same tissue type (for example NCR to NCR), adjacent types (NCR to ED, or ED to ET), and the special pair NCR to ET (because the necrotic core is directly surrounded by the enhancing rim). Connecting incompatible tissues would add noise.

**Edge Attributes (4 dimensions per edge)**:
- Distance: the normalized centroid-to-centroid distance.
- Angle: the direction of the connection measured by arctangent, normalized by pi.
- Z gap: the normalized depth distance between the two nodes.
- Same tissue flag: 1.0 if both endpoints have the same tissue type, 0.0 otherwise.

## 3. Supervoxel Aggregation

The `IntraNodeAggregator` class converts the variable-length set of supervoxel features within each node into a fixed-size 64-dimensional embedding. This is inspired by the SVGFormer paper.

Each segmentation node has a different number of supervoxels (denoted K_i for node i). The aggregator handles this variable length using a Transformer architecture with a special classification token.

The processing steps for each node are:

1. **Linear projection**: Each supervoxel feature vector (25 dimensions) is projected to 64 dimensions through a learned linear layer.

2. **CLS token prepending**: A learnable "classification token" (CLS) is prepended to the sequence of projected supervoxel features. The CLS token is a 64-dimensional vector that is initialized randomly and updated during training. The resulting sequence has length K_i + 1.

3. **Transformer encoding**: The sequence is passed through a 2-layer Transformer encoder with 4 attention heads, GELU activation, and dropout of 0.1. Each layer has a feedforward dimension of 128 (twice the embedding dimension). The Transformer allows each supervoxel to attend to every other supervoxel in the same node, learning which ones are most relevant.

4. **Output extraction**: The CLS token's output embedding is passed through a final linear layer to produce the 64-dimensional node embedding. The CLS token effectively "summarizes" the entire set of supervoxels.

5. **Attention weight computation**: For explainability, attention weights are computed by taking the dot product of each supervoxel's output embedding with the CLS output, followed by softmax normalization. These weights tell us how much each supervoxel contributed to the final node representation.

The key advantage of this approach over simple mean or max pooling is that the Transformer can learn to selectively attend to the most diagnostically important supervoxels. For example, in a large edema region, the model might focus on the supervoxels at the tumor-edema boundary where infiltration is occurring, rather than averaging over the entire uniform edema volume.

## 4. OCN Structural Features

The `StructuralFeatureComputer` class computes topology-based features for candidate edges. OCN stands for Orthogonalized Common Neighbors, a technique that extracts structural information that is not already captured by node embeddings.

For each candidate edge between nodes i and j, five features are computed:

**Common Neighbor Count (dim 0)**

The number of nodes that are simultaneously neighbors of both i and j, divided by the maximum degree in the graph. Common neighbors provide evidence that two nodes belong to the same community. If many nodes are connected to both i and j, it is likely that i and j should also be connected.

**Jaccard Coefficient (dim 1)**

The number of common neighbors divided by the total number of unique neighbors of i and j combined. This is a normalized version of the common neighbor count that accounts for node degree. Two high-degree nodes might share many common neighbors just by chance; Jaccard corrects for this.

**Adamic-Adar Index (dim 2)**

A weighted sum over common neighbors, where each common neighbor w contributes 1 divided by the logarithm of w's degree. This gives more weight to common neighbors that have low degree (are "rare"), because a shared neighbor that is itself connected to many other nodes is less informative than a shared neighbor that is connected to very few.

**OCN Residual (dim 3)**

This is the novel contribution from the OCN paper. The idea is that standard common neighbor features double-count information already captured by the node embeddings.

The computation works as follows. First, the mean embedding of all common neighbors is computed. This is called the "CN signal." Next, this CN signal is projected onto the 2-dimensional subspace spanned by the embeddings of nodes i and j (using QR decomposition for numerical stability). The projection captures the part of the CN signal that is already explained by the endpoint embeddings. The residual is the CN signal minus this projection. The OCN residual feature is the Euclidean norm of this residual vector.

If the residual is zero, it means the common neighbors' embeddings lie entirely in the span of the endpoint embeddings, and they add no new structural information. A large residual means the common neighbors encode topology that the endpoints alone cannot explain, making this edge structurally significant.

**Path-Normalized Common Neighbors (dim 4)**

The raw common neighbor count divided by the number of 2-hop paths between i and j. A 2-hop path from i to j is any path i, w, j where w is any node (not just a common neighbor). In dense graphs, the raw CN count tends to be inflated because there are many 2-hop paths between any pair of nodes. Path normalization corrects for this by measuring whether the observed CN count is surprisingly high or just expected given the local density.

## 5. Intra-Node Topology

The `compute_intra_node_topology` method computes a 4-dimensional topological fingerprint for each node based on its internal supervoxel graph. These features characterize the internal structure of each tissue region.

**CN Density (dim 0)**

The average common neighbor count across all pairs of supervoxels within the node. High CN density means the supervoxels are richly interconnected with many shared neighbors, indicating a cohesive, well-structured tissue region.

**Connectivity Ratio (dim 1)**

The actual number of edges in the internal supervoxel graph divided by the maximum possible number of edges. A ratio of 1.0 would mean every supervoxel is connected to every other supervoxel (a complete graph). A low ratio means the internal graph is sparse, which may indicate that the tissue region is fragmented or contains distinct subregions.

**Degree Variance (dim 2)**

The standard deviation of the degree (number of connections) across all supervoxels in the node. Low variance means all supervoxels have roughly the same number of connections, indicating a homogeneous internal structure. High variance means some supervoxels are highly connected "hubs" while others are peripheral, indicating an irregular or heterogeneous tissue structure.

**Spectral Gap (dim 3)**

The second smallest eigenvalue of the graph Laplacian matrix of the internal supervoxel graph. This is also known as the algebraic connectivity or the Fiedler value.

The graph Laplacian is constructed by taking the degree matrix (a diagonal matrix where each entry is a node's degree) minus the adjacency matrix. Its eigenvalues reveal the connectivity structure of the graph. The smallest eigenvalue is always zero. The second smallest eigenvalue (the spectral gap) measures how well-connected the graph is overall.

A spectral gap close to zero means the graph can be easily split into disconnected components, which may indicate a multifocal tumor with separate islands. A large spectral gap means the graph is well-connected and difficult to partition, which indicates a solid, continuous tumor mass.

These four topology features are concatenated with the 64-dimensional aggregator embedding to form the final 68-dimensional node feature vector that enters the GATv2 encoder.

## 6. GATv2 Encoder

The `GATv2Encoder` is a 3-layer Graph Attention Network version 2 (GATv2) with residual connections and edge attribute awareness.

GATv2 is an improvement over the original GAT architecture. In the original GAT, the attention weight between two nodes depends only on the target node's features. In GATv2, the attention weight depends on both the source and target node features, allowing the model to learn asymmetric relationships. For example, the importance of the ET to NCR connection may differ from the NCR to ET connection.

The encoder processes node features as follows:

1. **Input projection**: The 68-dimensional node features are linearly projected to the hidden dimension of 128.

2. **Three GATv2 layers**: Each layer applies multi-head attention with 4 heads, where each head operates on 32 dimensions (128 divided by 4). The 4-dimensional edge attributes (distance, angle, slice gap, same tissue flag) are incorporated into the attention computation, allowing the model to modulate attention based on spatial relationships. Each layer includes LayerNorm and a residual connection (the input is added back to the output). Between layers, ELU activation and dropout (0.2) are applied.

3. **Output projection**: The 128-dimensional hidden features are projected down to the 64-dimensional embedding space.

The output is a 64-dimensional embedding for each node, plus optionally the attention weight matrices from each layer for visualization.

## 7. Multi-Signal Edge Decoder

The `MultiSignalDecoder` combines six different signals to predict whether an edge should exist between two nodes. Each signal captures a different type of evidence for the connection.

**Signal 1: Hadamard product (64 dims)**
The element-wise product of the source and destination node embeddings: z_i multiplied by z_j. Each dimension is high when both nodes have high values in that dimension, capturing feature agreement.

**Signal 2: Concatenation (128 dims)**
The source and destination embeddings concatenated: [z_i, z_j]. This preserves the full information from both nodes without any lossy combination, allowing the MLP to learn arbitrary pairwise functions.

**Signal 3: Common Neighbor Pool (64 dims)**
The mean embedding of all common neighbor nodes. If nodes i and j share neighbors w1 and w2, this signal is the average of z_w1 and z_w2. This encodes the topological context of the edge.

**Signal 4: Structural Embedding (64 dims)**
The 5-dimensional OCN structural features (CN count, Jaccard, Adamic-Adar, OCN residual, path-normalized CN) projected to 64 dimensions through a learned linear layer.

**Signal 5: Tissue Pair Embedding (64 dims)**
A learned embedding for the tissue type pair. There are 3 tissue types and therefore 9 possible ordered pairs (NCR to NCR, NCR to ED, NCR to ET, ED to NCR, and so on). Each pair has its own 64-dimensional embedding that is learned during training. This allows the model to learn that certain tissue pairs (like ET to NCR) are intrinsically more likely to be connected than others (like NCR to ED).

**Signal 6: Edge Type Embedding (32 dims)**
A learned embedding for whether the edge is intra-slice (both endpoints in the same axial slice) or inter-slice (endpoints in different slices). This allows the model to apply different link prediction strategies for lateral connections versus depth connections.

All six signals are concatenated into a 416-dimensional vector (64 + 128 + 64 + 64 + 64 + 32 = 416). This vector is then processed by a three-layer MLP:

- LayerNorm on the 416-dim input
- Linear layer from 416 to 128, followed by GELU activation and dropout (0.3)
- Linear layer from 128 to 64, followed by GELU activation and dropout (0.2)
- Linear layer from 64 to 1, producing a single logit value

The logit is passed through a sigmoid function to obtain the link probability.

## 8. Full Model

The `EdgePredictor` class orchestrates the complete forward pass. It contains three submodules: the IntraNodeAggregator, the GATv2Encoder, and the MultiSignalDecoder.

The forward pass proceeds as follows:

1. The aggregator processes the supervoxel features for each node, producing 64-dimensional node embeddings and attention weights.
2. The structural feature computer calculates the 4-dimensional intra-node topology features from the internal supervoxel graphs.
3. The node embeddings (64 dims) and topology features (4 dims) are concatenated to form 68-dimensional node feature vectors.
4. The GATv2 encoder processes these 68-dim features along with the graph structure and edge attributes, producing 64-dimensional final node embeddings.
5. The edge decoder takes the node embeddings, OCN structural features, common neighbor lists, tissue labels, and inter-slice flags, and produces logit predictions for positive edges (actual edges in the graph) and negative edges (randomly sampled non-edges).

## 9. Training and Evaluation

**Training Loop**

The model is trained with per-graph forward and backward passes (not batched, because graphs vary in size). For each graph, positive edges are the actual edges in the graph, and negative edges are sampled using degree-biased negative sampling.

Degree-biased negative sampling means that high-degree nodes are more likely to appear in negative edge samples. This produces harder negatives than uniform random sampling, because two high-degree nodes that are not connected are a more informative training signal than two random nodes that happen to not be connected.

The loss function is binary cross-entropy with logits, applied separately to positive edges (with target 1) and negative edges (with target 0), then summed. The optimizer is AdamW with learning rate 5e-4 and weight decay 1e-4. A OneCycleLR scheduler adjusts the learning rate during training. Gradient clipping with a maximum norm of 1.0 prevents exploding gradients.

**Evaluation Metrics**

The model is evaluated on several metrics:
- Overall AUC-ROC (Area Under the Receiver Operating Characteristic Curve): measures the model's ability to distinguish positive from negative edges across all threshold values.
- Average Precision (AP): the area under the precision-recall curve, which is more informative when positive and negative edges are imbalanced.
- Intra-slice AUC: performance on edges where both endpoints are in the same axial slice.
- Inter-slice AUC: performance on edges that cross slice boundaries, which is generally harder.
- Tissue-pair scores: mean confidence per tissue type pair (for example, the average predicted probability for all ET to ED edges), which reveals which tissue relationships the model is most and least confident about.

## 10. 3-Level Explanation System

The `HierarchicalExplainer` class generates explanations at three levels of granularity for each predicted edge.

**Level 1: Structural Evidence ("Why are these regions connected?")**

This level reports the OCN structural features for the predicted edge: the common neighbor count, Jaccard coefficient, Adamic-Adar index, OCN residual, and path-normalized CN. It also reports the tissue types of both endpoints, their spatial distance, and whether the edge is intra-slice or inter-slice.

Example output:
```
Level 1 -- Structural Evidence (strong):
  Distance: 0.042 | CN: 0.80 | Jaccard: 0.400
  Adamic-Adar: 1.443 | OCN residual: 0.231
  Path-norm CN: 0.667
```

**Level 2: Supervoxel Attribution ("Which parts of each region drove the connection?")**

This level reports the top-3 supervoxels in each endpoint node that received the highest attention weights from the IntraNodeAggregator. It also reports the attention entropy, which measures whether the model is focusing on a few specific supervoxels (low entropy means focused attention) or distributing attention evenly across many supervoxels (high entropy means distributed attention).

Example output:
```
Level 2 -- Supervoxel Attribution:
  Source (ET): focused attention (H=0.72)
    SV#3: weight=0.412
    SV#7: weight=0.289
    SV#1: weight=0.156
  Target (NCR): distributed attention (H=1.84)
    SV#12: weight=0.198
    SV#5: weight=0.171
```

**Level 3: Spatial Heatmap ("Where in the MRI is the evidence?")**

This level maps the supervoxel attention weights back to voxel coordinates in the original MRI volume. For each important supervoxel, all voxels belonging to that supervoxel are painted with its attention weight value. The result is a 3D heatmap of the same dimensions as the original MRI, where bright regions correspond to the most important voxels for the predicted connection.

**Visualization**

The `plot_hierarchical_explanation` function generates a 4-panel figure:
- Panel 1: The graph topology with all nodes colored by tissue type and the explained edge highlighted in blue.
- Panel 2: The supervoxel attention heatmap overlaid on the segmentation mask contours, or a horizontal bar chart of attention weights if no 3D volume is available.
- Panel 3: A bar chart of the five OCN structural features, each in a different color.
- Panel 4: The full text explanation showing all three levels in monospace font.

## 12. Ablation Baseline (Flat Path)

The flat graph baseline code lives in `ablation/flat_graph.py` and is used only for ablation experiments (configs A and C). It provides a non-hierarchical comparison where each 2D connected component becomes a node with 35-dim handcrafted features (intensity, boundary, cross-modal, morphology) instead of using the Transformer-aggregated supervoxel embeddings.

The ablation study framework is in the `ablation/` folder:
- `config.py`: defines 5 ablation configurations that toggle SV aggregation, topology, and OCN
- `model.py`: wraps EdgePredictor with conditional switches for each component
- `runner.py`: orchestrates training across all configs and seeds
- `report.py`: generates comparison tables, significance tests, and plots
